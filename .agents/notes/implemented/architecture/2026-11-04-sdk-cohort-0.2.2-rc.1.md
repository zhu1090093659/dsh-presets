# Agent Note: SDK cohort 0.2.2-rc.1

Status: implemented

## Problem

The preset center tracked 0.2.2-alpha.3 while the supported host moved to 0.2.2-rc.1 (with Cordis 4.1.0 and stable vendor packages). Dependency declarations, lockfile resolutions, committed build output and badges need to move in lockstep with the main family.

## Decision

Consumed SDK development dependencies move to `^0.2.2-rc.1`, Cordis to `^4.1.0`, and the host engine and peer floors to `>=0.2.2-rc.1`. The lockfile, release-age exclusion ledger, committed `lib/` output, README badges and bilingual pairing hashes move together. Preset compositions (`local-lite` and roleplay presets) require no structural change because the `dsh-v0.2.2-rc.1` source tree is identical to `dsh-v0.2.2-alpha.3`.

## Alternatives considered

**Leave the preset center on 0.2.2-alpha.3.** Rejected: keeping alpha floors and lockfile entries diverges from the main family and the 0.2.2-rc.1 host.

**Publish a new preset-center version.** Rejected: no release was requested and the package version stays unchanged.

## Consequences

`pnpm install --frozen-lockfile --ignore-scripts` passes supply-chain policy verification. `pnpm build`, `pnpm preset:check` (33 presets), the preset-catalog script tests, `pnpm typecheck` and `pnpm test` pass. No package is published to npm; dsh-web links the rebuilt working tree through its satellite profile workflow.
