# Agent Note: SDK cohort 0.2.2-rc.2

Status: implemented

## Problem

The preset center tracked 0.2.2-rc.1 while the host family moved to 0.2.2-rc.2. rc.2 is a breaking release on the SDK surface: it removes the internal subpath exports (such as `@deepseek-ai/dsh-subagent/internal`) and changes the call shape of a few runtime APIs (`startActivation` field nesting, `drainChildren` and `drainDescendants`). Dependency declarations, lockfile resolutions, the release-age ledger, the declared host floor and the committed build output have to move in lockstep with the main family.

## Decision

The seven consumed `@deepseek-ai/*` development dependencies move to `^0.2.2-rc.2`, the `@deepseek-ai/dsh` peer dependency and `dsh.engines.dsh` move to `>=0.2.2-rc.2`, and the lockfile follows. `@deepseek-ai/cordis` stays at `^4.1.0`.

The release-age exclusion ledger in `pnpm-workspace.yaml` is rewritten with the cohort rather than renamed in place: the 322 rc.1 entries become the 329 rc.2 versions the lockfile actually resolves. rc.2 drops seven packages from this graph (the five `dsh-experimental-*-agent-team` faces plus `dsh-deepseek-account-platform`, `dsh-api-account-controller` and `dsh-office-to-pdf`), so their stale entries are removed, and fourteen new ones are recorded (`dsh-agent-team`, `dsh-client-ui-agent-team`, `dsh-tool-agent-team`, `dsh-cua`, `dsh-cua-bundle`, `dsh-computer-use`, `dsh-experimental-cua-macos`, `dsh-error`, `dsh-office-kit`, `dsh-tool-office`, `dsh-mcp-manager`, `dsh-terminal-panel`, `dsh-client-ui-account-notifications`, `dsh-util-ripgrep`). The DSH badge in both README files moves to `>=0.2.2-rc.2` and the bilingual pairing hashes are re-recorded.

Plugin source needs no adaptation. This repository consumes only `dsh-agent-preset-registry`, `dsh-host-webserver`, `cordis`, and the client faces `dsh-client-ui-slots`, `dsh-client-ui-renderer/client`, `dsh-client-locale/client`, `dsh-client-ui-primitives` and `dsh-client-connection`; it never reaches an internal subpath and never calls `startActivation`, `drainChildren` or `drainDescendants`. Every module the plugin imports still resolves at rc.2 and typechecks unchanged, and `src/`, `tests/`, `shared/`, `cordis.patch.yml` and `presets/` stay byte-identical.

## Alternatives considered

**Leave the preset center on 0.2.2-rc.1.** Rejected: the host family is on rc.2, so a rc.1 floor and a rc.1 lockfile would declare compatibility a version behind the host it ships into.

**Rename the ledger entries in place, keeping the seven that rc.2 no longer resolves.** Rejected: the ledger records the cohort actually installed, and dead entries make the next upgrade read a graph that no longer exists.

**Publish a new preset-center version with the cohort move.** Rejected: no release was requested. The package version stays `0.4.17` and the release is coordinated outside this change.

## Consequences

`pnpm install --frozen-lockfile --ignore-scripts` resolves the rc.2 cohort and passes supply-chain policy verification. `pnpm build` reproduces the committed `lib/` byte for byte, so `git diff --exit-code -- lib` is clean and the published bytes do not change. `pnpm preset:check` (33 presets), the preset-catalog script tests, `pnpm typecheck` and `pnpm test` (55 tests) pass. Nothing is published to npm and no tag is created; dsh-web links the rebuilt working tree through its satellite profile workflow.
