# Agent Note: SDK cohort 0.2.2-alpha.3

Status: implemented

## Problem

The preset center tracked 0.2.1-rc.3 while the supported host moved to 0.2.2-alpha.3. The new host splits PTC execution into an agent-scoped executor and raises the Node floor, so the cohort move needs both a dependency update and an explicit decision for every preset composition.

## Decision

The consumed SDK development dependencies move to `^0.2.2-alpha.3`, Cordis to `^4.0.6-alpha.2`, and the host engine and peer floors to `>=0.2.2-alpha.3`. CI runs Node 24.9.0. The lockfile, release-age ledger, README badges and pairing hashes move together.

The preset catalog is audited against the published composition: `local-lite` deliberately mounts no PTC executor and stays native, while its `run_code` restriction guard remains for an outer PTC scope. The roleplay presets still declare only their persona and need no tool-roster migration. The eleven-module browser platform table is unchanged.

## Alternatives considered

**Add the PTC executor to every preset.** Rejected: it would change local-lite's native tool surface and token budget for no required capability; the executor belongs only to a composition that selects PTC.

**Leave the old `tools.mode` model in the preset documentation.** Rejected: the current host uses composition-scoped native and PTC executors, so the comments now describe that contract instead of the removed global switch.

**Publish a new preset-center package as part of the cohort move.** Rejected: no release was requested and the package version stays unchanged.

## Consequences

`pnpm install --frozen-lockfile --ignore-scripts` passes the supply-chain policy check. `pnpm typecheck`, `pnpm test` (55 tests), `pnpm build`, `pnpm preset:check` (33 presets), and the preset-catalog node tests pass. The host now requires Node 24.9 or later. No package is published to npm; dsh-web consumes the updated working-tree content through its normal satellite workflow.
