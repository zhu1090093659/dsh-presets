# Agent Note: SDK cohort 0.2.1-rc.3

Status: implemented

## Problem

The preset center tracked 0.2.1-rc.2 while the supported host moved to 0.2.1-rc.3. Its host half depends on the agent-preset registry and its browser half shares the official module table, so the cohort move needs to verify both surfaces and leave a reproducible lockfile and release-age ledger.

## Decision

The seven consumed SDK development dependencies move to `^0.2.1-rc.3`. `dsh.engines.dsh` and the `@deepseek-ai/dsh` peer both declare `>=0.2.1-rc.3`; the bilingual README badges and pairing hashes follow. Cordis stays `^4.0.5`, matching the cohort.

The lockfile is rebuilt from a clean resolution at rc.3. The release-age ledger retains its append-only union form: existing rows now name `0.2.1-rc.2 || 0.2.1-rc.3`, and the newly published `dsh-client-ui-entry-customization` has an rc.3 row. An audit of the lockfile finds all 298 resolved rc.3 packages covered.

The agent-preset registry declarations and the eleven-row browser platform table are unchanged. `shared/web-platform.ts` moves only its verification provenance, and no runtime source needs adaptation.

## Alternatives considered

**Prune every rc.2 member from the release-age union.** Rejected: the ledger is the tool-maintained history of resolved versions, and pruning old members buys nothing while violating its established append-only convention.

**Change preset registration for the new conversation features.** Rejected: the rc.3 registry contract is unchanged, and the preset center does not implement the conversation header or composer-submission owner that gained fields.

**Publish a new preset-center package as part of the cohort move.** Rejected: no release was requested and the package version stays unchanged.

## Consequences

`pnpm install --frozen-lockfile --ignore-scripts` passes the supply-chain policy check. `pnpm typecheck`, `pnpm test` (55 tests), `pnpm preset:check` (32 presets), `node --test scripts/preset-catalog.test.mjs` (9 tests), and `pnpm build` pass. The rebuilt committed `lib/` is unchanged.

No `@linxin666` version changes and nothing is published to npm. The repository owns its cohort commit; dsh-web moves the submodule pin after that commit is available on this repository's remote `main`.
