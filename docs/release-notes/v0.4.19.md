预置中心随 dsh-web 家族对齐到统一版本 0.4.19，与全家桶 0.4.19 同版本发布。区间 `v0.4.18..HEAD` 内只有一个功能提交——`cf0a156 feat(preset-center): add plugin page display metadata`，经 PR #6 合入（合并提交 `5e3a413`）——它给插件补上宿主插件列表页要读的显示元数据，本版就是把这份改动发出去。改动面一共四处：新增 `locale/en.json` 与 `locale/zh.json`，各自带 `meta.title` 与 `meta.description`；`package.json` 的 `exports` 增加 `./locale/en.json` 与 `./locale/zh.json` 两个键——宿主先读 `locale/en.json`，再枚举 `locale/` 下每个 `*.json` 并经本包自己的 `exports` 解析，所以键与文件必须一一对应；同一文件的 `files` 白名单补上 `locale`，否则 npm 打包会整目录丢掉；新增 `tests/display-metadata.spec.ts` 作为这四点一致性的闸门。`src/`、`shared/`、`presets/`、`cordis.patch.yml`、`icon.svg` 与中英两份 README 逐字未动，预置目录仍是 33 条。

> **用户可见变更**：宿主插件列表里预置中心那一行的标题与灰色描述，从「npm 包名 + 英文包描述」的兜底显示，改为读 `locale/<lang>.json` 的 `meta.title` 与 `meta.description`——英文界面显示 `Preset center` 与 `Browse and enable community presets.`，中文界面显示 `预设中心` 与 `浏览并启用社区预设`。此前没有这条通道时，元数据整读会失败并静默回落到兜底文案，因此上面四项（两份文件、两个 `exports` 键、`files` 白名单条目）缺任何一项，那一行都会退回旧显示。

> **兼容性**：冻结标识全部未改名：包名 `@linxin666/dsh-client-ui-preset-center`；安装与挂载方式（`files` 仍是 `lib`、`cordis.patch.yml` 与 `icon.svg`，新增的只有 `locale`；宿主侧仍按 `cordis.patch.yml` 里 `ui-preset-center` 这一补丁行的名义挂载）；持久化文件名与键名；线协议字段与仅回环可用的 `/api/preset-center/*` 路由。`exports` 只新增两个键，既有键的取值与通配未变，按原路径解析的消费方不受影响。`dsh.engines.dsh` 与 `@deepseek-ai/dsh` 对等依赖的下限仍是 `>=0.2.2-rc.2`，依赖表与 `pnpm-lock.yaml` 未动。既有的 `icon` 字段（`icon.svg`，相对路径、包内文件）本版未改动，只是新增的测试把它连同 `files` 白名单一起纳入了闸门。

> **升级提示**：这次显示元数据无需任何适配——宿主与本插件升级后，插件列表页那一行即显示本地化标题与描述；覆盖安装时 `locale/` 随包体一起更新，`pnpm build` 重建的 `lib/` 与上一版逐字节相同。

The preset center aligns with the unified dsh-web family version 0.4.19, on the same version as the family's 0.4.19. The range `v0.4.18..HEAD` holds exactly one feature commit - `cf0a156 feat(preset-center): add plugin page display metadata`, merged through PR #6 (merge commit `5e3a413`) - which gives the plugin the display metadata the host's plugin list reads; this release ships that change. Four things change: `locale/en.json` and `locale/zh.json` are added, each carrying `meta.title` and `meta.description`; the `exports` map in `package.json` gains `./locale/en.json` and `./locale/zh.json`, because the host reads `locale/en.json` first and then enumerates every `*.json` in that directory and resolves each one through this package's own `exports` map, so the keys and the files must match one for one; the `files` whitelist in the same manifest gains `locale`, without which npm drops the whole directory; and `tests/display-metadata.spec.ts` is added as the gate over those four points. `src/`, `shared/`, `presets/`, `cordis.patch.yml`, `icon.svg` and both README files are unchanged word for word, and the catalog still holds 33 presets.

> **User-visible change**: the title and grey description on the preset center's row in the host's plugin list move from their fallback (the npm package name plus the English package description) to `meta.title` and `meta.description` from `locale/<lang>.json` - the English UI shows `Preset center` and `Browse and enable community presets.`, the Chinese UI shows `预设中心` and `浏览并启用社区预设`. Without that channel the metadata read failed as a whole and fell back silently, so dropping any of those four points (the two files, the two `exports` keys, the `files` entry) puts that row back on the old display.

> **Compatibility**: every frozen identity keeps its name: the package `@linxin666/dsh-client-ui-preset-center`; the install and mount path (the `files` field still carries `lib`, `cordis.patch.yml` and `icon.svg`, with only `locale` added, and the host still mounts the plugin under the `ui-preset-center` patch row in `cordis.patch.yml`); persisted file names and keys; the wire-protocol fields and the loopback-only `/api/preset-center/*` routes. > **Upgrade note**: nothing needs adapting for this display metadata - once the host and the plugin are upgraded, that row in the plugin list renders the localized title and description; an over-install updates `locale/` with the package body, and the `lib/` rebuilt by `pnpm build` is byte-identical to the previous release.
